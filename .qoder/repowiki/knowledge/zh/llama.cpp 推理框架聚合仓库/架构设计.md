顶层 CMakeLists.txt 是唯一的构建编排点：通过 `add_subdirectory` 按依赖顺序引入 ggml（底层张量图/后端）、src（llama_core）、vendor、common（common_lib），再条件性挂载 tests、examples、tools（cli_tools）、app；同时通过 LLAMA_USE_SYSTEM_GGML 选项允许外部 ggml 作为系统包链接，使本仓库既可自包含也可被上层项目引用。

跨子模块的统一契约集中在两个层面：
- C API 边界：include/llama.h 与 include/llama-cpp.h 由 src 暴露，common/lib、tools、examples、tests 均通过同一头文件调用，构成对外稳定 ABI。
- 构建开关矩阵：LLAMA_BUILD_COMMON / LLAMA_BUILD_TESTS / LLAMA_BUILD_EXAMPLES / LLAMA_BUILD_TOOLS / LLAMA_BUILD_SERVER / LLAMA_BUILD_APP / LLAMA_BUILD_UI / LLAMA_BUILD_MTMD 等选项在顶层集中声明，各子目录据此决定是否参与构建，避免循环依赖。

Python 侧通过 pyproject.toml + requirements.txt 提供独立的 gguf_py 包与 convert_hf_to_gguf.py 等脚本，与 C/C++ 构建解耦但共享 GGUF 格式规范（由 gguf_py 与 model_converters 共同实现）。
