模块按职责分层组织：
- 运行时桥接层（`ggml-metal-device.{h,cpp,m}` + `ggml-metal-context.{h,m}`）封装 MTLDevice/MTLCommandQueue/MTLBuffer/MTLComputePipelineState/MTLResidencySet 等 Metal API，提供 `ggml_metal_device_t`、`ggml_metal_library_t`、`ggml_metal_pipeline_t`、`ggml_metal_encoder_t` 等句柄类型。
- 算子调度层（`ggml-metal-ops.{h,cpp}`）通过 `ggml_metal_op_init` / `ggml_metal_op_encode` 遍历 `ggml_cgraph`，每个 `ggml_op` 对应一个 `ggml_metal_op_*` 函数，负责填充参数结构体、选择 pipeline 并调用 encoder。
- 融合层（`ggml-metal-fusion.{h,cpp}`）以单一数据表声明可融合的 subgraph 模式（NORM+MUL、ADD chain、SSM_CONV+SiLU、MoE routing 等），由 graph optimizer 和 op encoders 共享同一份匹配逻辑，支持 STRUCTURAL/FULL 两种检查模式。
- 内核源码层（`kernels/*.metal`）存放所有 Metal shader；构建时由 `CMakeLists.txt` 通过 `xcrun metal` 编译为 `.air` 再链接成 `default.metallib`，或经 `GGML_METAL_EMBED_LIBRARY` 走汇编嵌入流程把 kernel 源内联进二进制。
- 公共常量与参数结构体集中在 `ggml-metal-impl.h`（`ggml_metal_kargs_*`、`FC_*` function constants、`OP_*` 宏），被 C++ 侧填充并由 Metal shader 读取。
- 设备能力探测在 `ggml-metal-tuning.{h,cpp}` 中完成，依据 `ggml_metal_device_props`（含 simdgroup_mm、has_tensor、gpu_family 等）决定使用 mul_mm / mul_mv / MMA / tensor API 等不同路径。
依赖方向单向：ops → device/fusion/tuning → impl/common；Metal shader 仅依赖 `common.h`、`dequantize.h`、`quantize.h`、`fa_common.metal` 等头文件。
