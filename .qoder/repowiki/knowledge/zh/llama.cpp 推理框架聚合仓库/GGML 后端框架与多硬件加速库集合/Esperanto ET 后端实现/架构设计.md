模块以 ggml-et.cpp 作为 ggml 后端入口，通过 `ggml_backend_buffer_type_i` / `ggml_backend_buffer_i` / `ggml_backend_t` 等结构注册设备、内存分配与 `graph_compute`；内部按职责拆分为：
- 驱动层（ggml-et.cpp）：初始化 `dev::IDeviceLayer`（PCIe 或 `createSysEmuDeviceLayer`），持有全局 `_drv`（runtime、device_layer、profiler、kernel_map），并通过环境变量 `GGML_ET_PROFILE` 输出 JSON 追踪。
- 算子分发层（ggml-et-ops.* + ggml-et-kernels.*）：每个 `ggml_op` 对应一个 `ggml_et_op_xxx` 函数，负责参数打包到 `ggml_et_*_params` 结构体，再调用 `ggml_et_load_kernel` / `ggml_et_launch_kernel` 或走 uberkernel 路径。
- 内存操作层（ggml-et-memops.*）：封装 memset/copy 等基础 memop 内核。
- 共享上下文（ggml-et-common.h）：定义 `ggml_backend_et_device_context`（设备级 stream、已加载 kernel 表、uberkernel ring）、`ggml_backend_et_uberkernel_context`（4-slot ring）等。
- 内核构建子系统（et-kernels/ + cmake/）：CMakeLists.txt 维护 KERNELS 列表，对每个 `.c/.S` 编译出 `.elf`，再用 `embed_one_kernel.cmake` 把 ELF 二进制嵌入为 C++ 数组，由 `ggml-et-kernels-embed.{h,cpp}` 暴露；同时用模板生成 uberkernel 枚举映射 `ggml-et-uberkernel-kernel-map.{h,cpp}`。
依赖方向单向：ggml-et.cpp → ops/kernels/memops → common → ET runtime (`rt::IRuntime`, `dev::IDeviceLayer`)；et-kernels 子目录是独立交叉编译单元，不反向依赖上层。
