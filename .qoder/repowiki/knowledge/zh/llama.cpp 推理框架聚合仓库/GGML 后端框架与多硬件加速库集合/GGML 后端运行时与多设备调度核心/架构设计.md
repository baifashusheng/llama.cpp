模块以 `include/ggml-backend.h` 为唯一对外 C API 边界，定义 `ggml_backend_reg_t` / `ggml_backend_dev_t` / `ggml_backend_buffer_type_t` / `ggml_backend_buffer_t` / `ggml_backend_t` / `ggml_backend_event_t` 等句柄类型及 `ggml_backend_sched_t` 调度器接口；内部实现位于 `src/`：
- `ggml-backend.cpp` + `ggml-backend-dl.cpp` + `ggml-backend-reg.cpp`：后端注册表、动态库加载（`ggml_backend_load/unload/load_all`）、设备枚举与按名称/类型初始化。
- `ggml-backend-meta.cpp`：Meta 后端，将多个物理设备组合成张量并行元设备。
- `ggml.c` / `ggml.cpp` / `ggml-alloc.c` / `gguf.cpp` / `ggml-opt.cpp` / `ggml-threading.cpp` / `ggml-quants.*`：张量图、分配器、量化、优化、线程原语等基础运行时。
- 每个 `ggml-<backend>/` 子目录是一个独立后端实现（CPU/CUDA/Metal/Vulkan/SYCL/OpenCL/HIP/MUSA/BLAS/CANN/ET/RPC/VirtGPU/WebGPU/zDNN/ZenDNN/OpenVINO/Hexagon），通过 `ggml_add_backend()` 在顶层 `CMakeLists.txt` 统一注册；当启用 `GGML_BACKEND_DL` 时作为 MODULE 共享库输出，否则静态链接进 `ggml`。
- `cmake/common.cmake`、`FindNCCL.cmake`、`GitVars.cmake`、`ggml-config.cmake.in` 提供构建辅助与包导出。
依赖方向单向：后端 → `ggml-base`（核心）→ 系统库；后端之间不直接互访，仅通过 `ggml-backend.h` 暴露的句柄和 `ggml_backend_tensor_copy[_async]` 进行数据搬运。
