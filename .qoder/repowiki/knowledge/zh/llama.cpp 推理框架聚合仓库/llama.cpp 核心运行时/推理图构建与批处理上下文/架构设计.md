模块由四层组成，依赖方向自上而下为 context → graph → batch → io/adapter/chat。
- 批数据层（llama-batch.*）：定义轻量 `llama_ubatch`（token/embd/state/pos/seq_id 等指针视图 + 可选 owned data_t），以及高层构造器 `llama_batch_ext`；`llama_batch_allocr` 负责把外部 batch 规范化、校验并按 equal_seqs / seq 策略切分出多个 ubatch；`llama_batch_compat` 提供旧版 `llama_batch` 到新版 API 的 RAII 桥接。
- 图构建层（llama-graph.*）：以 `llm_graph_input_i` 抽象接口 + 大量具体子类（`llm_graph_input_embd`、`llm_graph_input_attn_kv`、`llm_graph_input_attn_k_dsa`、`llm_graph_input_dsv4`、`llm_graph_input_mem_hybrid*` 等）描述不同注意力/KV 缓存后端所需的输入张量；`llm_graph_params` 携带 arch/hparams/cparams/ubatch/mctx 等用于拓扑比较，`llm_graph_result` 持有已构建的 `ggml_cgraph`、compute ctx、输入/输出张量及 fused_nodes，并提供 `can_reuse()` 基于 `allow_reuse()` 判定是否可复用上一轮图。
- 上下文层（llama-context.*）：`llama_context` 是对外入口，封装 scheduler、backends、MoE cache、采样状态、logits/embedding 输出缓冲；通过 `process_ubatch()` 选择/构建图、调用 `graph_compute()` 执行，并维护 `gf_res_prev[2]`（区分带/不带 logits 的 arena）和 `gf_res_reserve` 做图重用；state_save/load 委托给 `llama_io_write_i`/`llama_io_read_i`。
- 支撑层：`llama-io.*` 定义纯虚 IO 接口供 state 序列化使用；`llama-adapter.*` 提供 LoRA/cvec 适配器；`llama-chat.*` 提供多模板对话格式化（ChatML、Llama-3、Mistral 等枚举）。
