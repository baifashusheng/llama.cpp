模块以三层结构组织：
- 底层元数据：`llama-kv-cells.h` 中的 `llama_kv_cells` 是环形槽位容器，维护每槽位的 pos/ext/shift/seq bitset 及按序列排序的 `seq_pos` 索引，所有上层缓存共享此数据结构。
- KV 缓存核心：`llama-kv-cache.{h,cpp}` 定义 `llama_kv_cache`（继承自 `llama_memory_i`）和 `llama_kv_cache_context`（继承自 `llama_memory_context_i`），通过 `prepare/find_slot/apply_ubatch/cpy_k/cpy_v` 等 API 完成 ubatch 到槽位的映射、图构建（RoPE shift、kq mask、pos bucket）以及 state_write/state_read 持久化；内部按层 (`kv_layer`) 持有 k/v ggml_tensor 及 per-stream 视图，并通过 `slot_info` + `stream_copy_info` 表达多流、多 stream 的批量布局。
- 变体实现：按注意力类型拆分为独立文件——`llama-kv-cache-dsa.cpp`（双缩放注意力）、`llama-kv-cache-dsv4.cpp`、`llama-kv-cache-msa.cpp`（多头/多查询）、`llama-kv-cache-iswa.cpp`（iSWA）、`llama-kv-cache-dsa-iswa.cpp`（DSA+iSWA 组合），每种变体提供自己的 context 实现并复用同一 cells 后端。
- 内存抽象层：`llama-memory.{h,cpp}` 定义 `llama_memory_i` / `llama_memory_context_i` 接口与 `llama_memory_params`，并由 `llama-memory-hybrid*`（hybrid、hybrid-idx、hybrid-iswa）组合多个子 memory 实现混合策略，`llama-memory-recurrent.cpp` 提供循环上下文支持。
- MoE 缓存：`llama-moe-cache.{cpp,h}` 独立于 KV cache，使用 pimpl 模式在 host 侧维护每个 layer 的专家 slot map，并在 ggml_backend_sched 的 copy callback 中按需将缺失专家上传至设备 buffer。
依赖方向：变体 → kv-cache → kv-cells；memory-* 组合 kv-cache 与其他 memory；moe-cache 完全独立，仅依赖 ggml-backend。
