模块以 `gguf/` 为纯 Python 包根，通过 `pyproject.toml` 暴露 `gguf` 包名与多个 CLI entry points（`gguf-dump`、`gguf-set-metadata`、`gguf-convert-endian`、`gguf-new-metadata`、`gguf-editor-gui`）。

内部按职责分层：
- 常量与枚举层：`constants.py` 集中定义 `GGUF_MAGIC`、`GGUF_VERSION`、`GGUFValueType`、`GGMLQuantizationType`、`Keys`、`RopeSectionOrder` 等所有协议级常量，被其余模块单向依赖。
- I/O 核心：`gguf_reader.py` 中的 `GGUFReader` 基于 `numpy.memmap` 零拷贝解析头部、KV 字段与张量数据；`gguf_writer.py` 中的 `GGUFWriter` 使用状态机 `WriterState`（NO_FILE→EMPTY→HEADER→KV_DATA→TI_DATA→WEIGHTS）分阶段写出，支持多分片（`SHARD_NAME_FORMAT`）、临时文件缓冲与大模型 dry-run。
- 数据类型桥接：`quants.py` 在 GGML 量化类型与字节形状之间转换；`tensor_mapping.py`、`vocab.py` 提供模型架构到张量名的映射；`lazy.py`、`utility.py` 提供辅助工具。
- 高层元数据：`metadata.py` 的 `Metadata` dataclass 从 HuggingFace model card / generation_config / JSON 覆盖文件自动推断并合并作者、采样、许可证等 KV 字段。
- CLI 脚本层：`scripts/` 下每个文件是独立可执行入口，仅依赖 `gguf` 公共 API，不反向依赖上层。
- 顶层 `__init__.py` 采用 `from .xxx import *` 扁平导出，使调用方直接 `import gguf` 即可访问 Reader/Writer/Constants/Quants/Vocab/Metadata。

依赖方向严格自上而下：scripts → metadata/utility/vocab → reader/writer → quants → constants；reader/writer 不互相依赖。
