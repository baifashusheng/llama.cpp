模块按职责划分为四个子目录：
- `cmake/`：CMake 工具链与生成逻辑，包括 `common.cmake`（统一警告、sanitize、依赖 ggml/cmake/common.cmake）、`build-info.cmake`（通过 git rev-parse/rev-list 注入 BUILD_COMMIT/BUILD_NUMBER/BUILD_COMPILER/BUILD_TARGET）、`git-vars.cmake`、`download-models.cmake`、`license.cmake`，以及按目标平台切分的 toolchain 文件（arm64-apple-clang.cmake、arm64-linux-clang.cmake、arm64-windows-llvm.cmake、arm64-windows-msvc-cuda.cmake、x64-windows-llvm.cmake、riscv64-spacemit-linux-gnu-gcc.cmake），并产出 `llama-config.cmake.in` 与 `llama.pc.in` 供下游 find_package/pkg-config 使用。
- `scripts/`：顶层构建与发布辅助脚本，按功能分目录——`apple/` 各平台 validate 脚本、`hip/gcn-cdna-vgpr-check.py`、`jinja/`、`snapdragon/`（完整的 Snapdragon/HXAGON 交叉编译 Python SDK，含 build.py/run.py/sdk.py 及 adb/qdc 测试）；根级脚本负责模型下载 (`get-*`)、量化/对比 (`compare-*`, `tool_bench.*`)、同步 ggml (`sync-ggml.sh`)、发布流程 (`release.sh`、`make-release-desc.sh`、`check-release-apiabi.sh`)、CI 辅助 (`build-info.sh`, `check-requirements.sh`) 等。
- `.devops/`：Dockerfile 集合（cuda/musa/rocm/openvino/vulkan/intel/s390x/cann/zendnn/llama-cli-cann）与 SRPM spec、tools.sh，用于在隔离容器中复现各后端构建环境。
- `ci/`：自托管 runner 上的重型工作流入口 `run.sh`，根据 `GG_BUILD_*` 环境变量（CUDA/ROCM/SYCL/VULKAN/WEBGPU/MUSA/KLEIDIAI/BLAS/OPENVINO 等）拼装 `CMAKE_EXTRA`，依次执行 ctest_debug/release、backend_ops、model-dependent tests、qwen3/bge/rerank 端到端验证。

依赖方向：`ci/run.sh` → CMake + ctest；`scripts/snapdragon/build.py` → CMake presets + Docker；`cmake/*.cmake` 被项目顶层 CMakeLists.txt include，不反向依赖脚本。
