模块由三个相互协作的子层组成：
- `server-task.*` 定义数据契约：`server_task_type` 枚举（COMPLETION/EMBEDDING/RERANK/DECISION/INFILL/CANCEL/CONTROL/METRICS/SLOT_*/GET_LORA/SET_LORA）描述入队任务；`task_params` 封装采样、聊天格式、LoRA 等参数；`server_task_result` 及其派生类（cmpl_final/cmpl_partial/embd/rerank/decision/error/metrics/slots/control/get_lora/apply_lora/router）通过虚函数 `to_json()`、`is_stop()`、`update()` 统一序列化与流式状态更新。
- `server-queue.*` 实现生产者-消费者模型：`server_queue` 维护 `queue_tasks`、`queue_tasks_deferred`、`queue_tasks_unhandled` 三个 deque，配合 `mutex_tasks` + `condition_variable` 驱动单 worker 线程循环；支持 idle sleep、`yield_to_queue` 让出给主线程、`on_new_task`/`on_update_slots`/`on_sleeping_state` 回调钩子；`server_response` 用 `unordered_set<int>` 跟踪等待任务并通过条件变量阻塞 `recv`；`server_response_reader` 是 RAII 包装器，暴露 generator 风格的 `post_task`/`next`/`wait_for_all`。
- `server-stream.*` 提供跨 HTTP 断连的流式会话：`stream_session` 作为按 `conversation_id` 键控的环形缓冲区，`stream_pipe_producer` 写入并拥有 session 生命周期，`server_res_spipe` 在 `server_http_res` 之上实现 tee-style pipe，使断连后仍可重放；对外暴露 `/v1/stream/*` 路由工厂（GET/POST lookup/DELETE）及 `X-Conversation-Id` 头解析。
依赖方向单向：stream → http；queue → task；task 仅依赖 common/llama/server-common，不反向依赖 queue 或 stream。
