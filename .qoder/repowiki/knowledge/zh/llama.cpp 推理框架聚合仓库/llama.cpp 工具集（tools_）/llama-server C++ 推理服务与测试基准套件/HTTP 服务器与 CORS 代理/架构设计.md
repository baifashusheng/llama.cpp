模块以 `server_http_context` 为核心抽象，通过 PImpl (`Impl`) 封装底层 `cpp-httplib::Server` 实例，支持多监听器（TCP / AF_UNIX socket）与可选 SSL（`CPPHTTPLIB_OPENSSL_SUPPORT`）。内部分层如下：
- 请求/响应模型：`server_http_req`、`server_http_res`（含 `next` 流式回调）定义统一的 handler 接口；`uploaded_file` 承载 multipart 上传。
- 生命周期：`init()` 解析 GCP Vertex AI 环境变量（`AIP_PREDICT_ROUTE`、`AIP_HTTP_PORT` 等），构造并配置每个 listener；`start()` 绑定端口、创建共享 `ThreadPool` 并启动监听线程；`stop()/join()` 负责优雅关闭。
- 中间件管线：在 `set_pre_routing_handler` 中按顺序执行 CORS → 就绪状态检查 → API Key 校验，再放行到业务 handler。
- 路由分发：`get/post/del` 将 httplib 原生请求适配为 `server_http_req`，并通过 `process_handler_response` 统一处理普通响应与 chunked 流式响应。
- 附加协议：`register_gcp_compat()` 根据已注册 handler 自动生成 camelCase 别名并挂载 `/predict` 入口，将 AIP 请求体拆分为并行 futures 后分派到已有 handler。
- CORS 代理：`server-cors-proxy.h` 提供独立的 `proxy_request()` 与 GET/POST handler，从 `x-llama-server-proxy-header-*` 前缀提取透传头，使用 `server_http_proxy` 转发到任意 http(s) 目标，超时默认 600s。
依赖方向：本模块仅向上暴露 `server_http_context` 与 CORS 代理函数，被上层 server.cpp 调用；不反向依赖具体业务 handler。
